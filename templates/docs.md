# Documentation starter

## Problem & audience

Describe the Bitcoin user, contributor, or operator problem. State who will use this documentation and why the current materials are insufficient.

## Plan & deliverables

- Write or revise the named guides.
- Publish them in the target repository under an open-source license.
- Include screenshots, examples, or runnable commands where useful.

## Verification

1. Open the listed documentation URLs.
2. Follow each command or setup path from a clean environment.
3. Confirm the guide covers the stated audience and links to source materials.

## Out of scope

Product implementation, ongoing support, and translations unless listed above.
